## Middleware
1. **Логирование** – выводит в консоль метод и путь запроса, а также статус ответа.  
2. **Добавление заголовка** – `X-Powered-By: ASP.NET Core Lab27`.  
3. **Проверка ключа** – если в Query-параметре `key` отсутствует или не равен `secret`, возвращается **401 Unauthorized**.

## Главные выводы
1. ASP.NET Core позволяет быстро создавать кроссплатформенные веб-серверы с высокой производительностью.  
2. Minimal API — простой и эффективный способ создания микросервисов и небольших приложений без избыточного кода.  
3. Middleware даёт гибкий контроль над обработкой каждого запроса: логирование, аутентификацию, модификацию ответа.  
4. Порядок регистрации middleware и маршрутов критичен — маршруты должны объявляться после `app.Use(...)`.  
5. Автоматическая сериализация объектов C# в JSON упрощает создание API.

## Ответы на вопросы

### 1. Чем Minimal API отличается от MVC в ASP.NET Core?
- **Minimal API** — минимум кода, нет контроллеров, подходит для микросервисов и небольших API.  
- **MVC** — полноценный паттерн с контроллерами, представлениями (Views), фильтрами, подходит для крупных веб-приложений с UI.

### 2. Что произойдёт, если поставить `app.MapGet(...)` до `app.Use(...)`?
Middleware не сможет обработать запрос к этому маршруту, потому что маршрут перехватит запрос раньше. Правильный порядок: сначала `Use`, затем `MapGet`.

### 3. Почему ASP.NET Core преобразует PascalCase в camelCase при сериализации JSON?
По умолчанию используется соглашение **camelCase** для совместимости с JavaScript-клиентами (стандарт де-факто в REST API). Поведение задаётся в `System.Text.Json` и может быть изменено настройкой `JsonSerializerOptions.PropertyNamingPolicy = null`.

### 4. Что означают коды ответа HTTP?
| Код | Значение |
|-----|-----------|
| 200 | OK — запрос успешно выполнен |
| 401 | Unauthorized — требуется аутентификация |
| 404 | Not Found — ресурс не найден |

### 5. Чем `dotnet run` отличается от `dotnet watch run`?
- `dotnet run` — однократный запуск; после изменения кода нужно остановить и перезапустить вручную.  
- `dotnet watch run` — запускает «наблюдатель», который автоматически перезапускает сервер при сохранении файлов (горячая перезагрузка).
